# CLAUDE.md

Guidance for Claude Code (and human contributors) working in this repository.

## What this project is

`aetherterm` is a cross-platform (Windows + Linux) serial / socket / telnet /
SSH terminal application. Its distinguishing feature — **not yet built** — is
a configurable frame of paged button grids (envisioned as roughly 4x5 per
page) beneath the main terminal window, where each button launches an
automation script against network or serial devices.

**Current state: scaffold only.** There is deliberately no business logic, no
GUI widgets beyond a stub, no terminal emulation, and no scripting engine.
Do not add any of that unless explicitly asked — the point of this repo state
is a rigorous, production-quality skeleton that future feature work builds
into.

## Golden rule: `uv` exclusively

Every environment, dependency, and tooling operation goes through `uv`. Do not
invoke `pip`, `venv`, `poetry`, `conda`, or a bare `python -m pytest` — always
prefix with `uv run`, or use `uv sync` / `uv add` / `uv lock` for environment
and dependency changes. All tool configuration lives in `pyproject.toml`;
there are intentionally no `.ruff.toml`, `mypy.ini`, `pytest.ini`, or similar
scattered config files. If a new tool is added, its config goes into
`pyproject.toml` too.

## Environment setup

```bash
uv sync                     # create .venv, install aetherterm (editable) + the dev dependency group
uv run pre-commit install   # install the git hooks defined in .pre-commit-config.yaml
```

`uv sync` also triggers the Hatchling build hooks, which generate
`src/aetherterm/_version.py` from the current Git state (see
[Versioning](#versioning-hatch-vcs) below). That file is git-ignored — never
hand-edit or commit it.

## Folder conventions

```
src/aetherterm/       Import package (src/ layout — never import from repo root).
  __init__.py          Exposes __version__.
  __main__.py          `python -m aetherterm` entry — calls gui.main().
  gui.py               THE GUI ENTRY POINT. gui.main() is what the installed
                        gui-script, `python -m aetherterm`, and the frozen
                        PyInstaller executable all invoke. Build the real
                        Tkinter application inside this function.
  py.typed             PEP 561 marker — this package ships inline type hints.
  _version.py          GENERATED by hatch-vcs at sync/build time. Git-ignored.
                        Never edit or commit it.
tests/                 Pytest tests, mirroring src/aetherterm's structure as it grows.
docs/                  User/developer documentation beyond README/CLAUDE.md.
architecture/          ADRs and design notes as features land.
scripts/               Small dev-facing helper scripts (e.g. build_exe.py).
aetherterm.spec        Checked-in PyInstaller spec — the reproducible build
                        recipe. This is the ONLY .spec file tracked in Git;
                        .gitignore excludes all others.
.github/workflows/     CI. Currently Windows-only (see CI section).
```

Rule of thumb: anything importable lives under `src/aetherterm/`; anything
that is tooling/CI-only lives at the repo root or under `scripts/` /
`.github/`.

## Task runner: `poethepoet`

`uv` has no built-in task-runner table (there is no `[tool.uv.scripts]`).
This project uses [poethepoet](https://poethepoet.natn.io/), configured
entirely under `[tool.poe.tasks]` in `pyproject.toml`. Every task is invoked
as `uv run poe <task>`:

| Task           | Command it runs                                                                  | Purpose                                 |
| -------------- | -------------------------------------------------------------------------------- | --------------------------------------- |
| `lint`         | `ruff check .`                                                                   | Lint                                    |
| `format`       | `ruff format .`                                                                  | Auto-format (writes)                    |
| `format-check` | `ruff format --check .`                                                          | Verify formatting (no writes)           |
| `typecheck`    | `mypy`                                                                           | Strict type-check of `src` + `tests`    |
| `test`         | `pytest`                                                                         | Run the test suite                      |
| `cov`          | `pytest --cov=aetherterm ...`                                                    | Tests with terminal + XML coverage      |
| `md`           | `mdformat .`                                                                     | Format Markdown (writes)                |
| `md-check`     | `mdformat --check .`                                                             | Verify Markdown formatting (no writes)  |
| `audit`        | `pip-audit`                                                                      | Check dependencies for known CVEs       |
| `build-exe`    | `pyinstaller aetherterm.spec --noconfirm --clean`                                | Build the single-file GUI executable    |
| `check`        | runs `lint`, `format-check`, `md-check`, `typecheck`, `cov`, `audit` in sequence | The full local quality gate, mirrors CI |

When adding a new dev task, add it to `[tool.poe.tasks]` in `pyproject.toml`
— do not introduce a separate Makefile, npm-style script runner, or shell
script for anything that fits this pattern.

## Quality tooling

- **Ruff** — lint + format, config under `[tool.ruff]` / `[tool.ruff.lint]` /
  `[tool.ruff.format]`. Line length 100, target `py312`.
- **Mypy** — strict mode, config under `[tool.mypy]`. `src/aetherterm/_version.py`
  is exempted (generated code) via `[[tool.mypy.overrides]]`.
- **Pytest + pytest-cov** — config under `[tool.pytest.ini_options]` /
  `[tool.coverage.run]` / `[tool.coverage.report]`. Tests live in `tests/`.
  Coverage must stay at or above 70% (`--cov-fail-under=70` on the `cov`
  task).
- **mdformat** — Markdown formatting, config under `[tool.mdformat]`.
- **pip-audit** — dependency vulnerability scanning against the locked
  environment (`poe audit`). No dedicated config; it reads the active venv.

Run everything at once with `uv run poe check` before opening a PR — this is
exactly what CI runs (see below).

## Pre-commit

`.pre-commit-config.yaml` wires up `pre-commit-hooks` (basic hygiene),
`gitleaks` (secret scanning — suppressions in `.gitleaks.toml`),
`ruff-pre-commit` (lint + format), `mirrors-mypy` (strict type-check), and
`mdformat`. Install once per clone with `uv run pre-commit install`; hooks
then run automatically on `git commit`. To run them ad hoc across the whole
tree: `uv run pre-commit run --all-files`.

## GUI entry point & the frozen executable

There is exactly one launch surface: `aetherterm.gui:main`. It is reachable
three ways, all equivalent:

1. Installed gui-script: `uv run aetherterm` (registered via
   `[project.gui-scripts]` in `pyproject.toml`).
2. Module execution: `uv run python -m aetherterm` (via `__main__.py`).
3. The frozen PyInstaller executable — `dist/aetherterm.exe` — built from
   `src/aetherterm/__main__.py` as the Analysis entry script in
   `aetherterm.spec`.

Because it's a `gui-scripts` entry (not `console-scripts`) and the spec sets
`console=False`, the built executable opens with no attached console window,
matching normal double-click GUI app behavior on both Windows and Linux.

### Building the executable

```bash
uv run poe build-exe
```

equivalent to:

```bash
uv run pyinstaller aetherterm.spec --noconfirm --clean
```

Output: `dist/aetherterm.exe` (Windows) / `dist/aetherterm` (Linux). The spec
is checked in specifically so the build is reproducible — do not regenerate
it with `pyi-makespec`; edit `aetherterm.spec` directly if the build needs to
change (e.g. adding `datas=` for bundled resources once the GUI grows).

`scripts/build_exe.py` is a thin, dependency-free wrapper around the same
spec, useful for contexts that prefer `uv run python scripts/build_exe.py`
over `poe`.

**Linux note:** Tkinter requires the system Tk package to be present in the
build environment (e.g. `sudo apt install python3-tk`) — this is a system
package, not something `uv` or PyInstaller can install for you.

## Versioning (`hatch-vcs`)

Version numbers are **never** hand-edited. `[tool.hatch.version] source = "vcs"` derives a PEP 440 version from Git tags/describe output, and
`[tool.hatch.build.hooks.vcs]` writes it to `src/aetherterm/_version.py` when
the package is (re)built. `src/aetherterm/__init__.py` imports `__version__`
from that generated file (falling back to `importlib.metadata` if the file
doesn't exist yet, e.g. a very first checkout before any sync).

### Releasing

```bash
git tag v0.2.0
git push --tags
```

A fresh clone, a CI run, or `uv run poe build-exe` picks up `0.2.0`
automatically — no file to edit, no PR needed just to bump a version.

**Caveat verified in this repo:** in an *existing* local checkout, plain
`uv sync` does not always regenerate `_version.py` after tagging, because
`uv` skips rebuilding the project wheel when no tracked source file changed
since the last sync — the tag alone doesn't invalidate that cache. Force it
with:

```bash
uv sync --reinstall-package aetherterm
```

Then verify:

```bash
uv run python -c "import aetherterm; print(aetherterm.__version__)"
```

## CI

`.github/workflows/ci.yml` runs on `windows-latest` only (Linux CI is future
work, not yet wired). It uses `astral-sh/setup-uv` with caching keyed off
`uv.lock`, checks out full history (`fetch-depth: 0`, required for `hatch-vcs`
to see tags), then runs, in order: `uv sync --frozen`, `poe lint`, `poe format-check`, `poe md-check`, `poe typecheck`, `poe cov`, `poe audit`, `poe build-exe`,
and finally uploads `dist/aetherterm.exe` as a workflow artifact. Keep local
`uv run poe check` + `uv run poe build-exe` green before pushing — that's the
same sequence CI enforces.

## Renaming the package

The placeholder name is `aetherterm` (distribution name == import name).
Renaming touches:

1. `src/aetherterm/` → `src/<new_name>/` (directory rename).
2. `pyproject.toml`: `[project] name`, `[project.gui-scripts]` key and target
   (`<new_name>.gui:main`), `[tool.hatch.build.hooks.vcs] version-file`,
   `[tool.hatch.build.targets.wheel] packages`, `[tool.ruff.lint.isort] known-first-party`, `[tool.mypy.overrides] module` for `_version`,
   `[tool.coverage.run] source`, and the `poe cov` command's `--cov=` flag.
3. `aetherterm.spec` → rename the file, update `Analysis` entry path and
   `EXE(name=...)`.
4. `.gitignore`: the `src/aetherterm/_version.py` line and the `!aetherterm.spec`
   negation.
5. `.github/workflows/ci.yml`: the `dist/aetherterm.exe` artifact path.
6. Import statements in `__init__.py`, `__main__.py`, `gui.py`, and
   `tests/test_import.py`.

There is no other place the name is hardcoded.

## What NOT to do in this repo right now

- Don't add terminal emulation, serial/socket/telnet/SSH transport code, the
  button-grid GUI, or a scripting engine unless explicitly asked — this repo
  is intentionally scaffold-only at this stage.
- Don't add config files outside `pyproject.toml` for tools that support
  `pyproject.toml` configuration (Ruff, Mypy, Pytest, coverage.py, mdformat,
  poethepoet all do).
- Don't hand-edit `src/aetherterm/_version.py` — it's generated and
  git-ignored.
- Don't regenerate `aetherterm.spec` from scratch — edit it in place so the
  build stays reproducible and reviewable.
